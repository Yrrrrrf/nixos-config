## 2. Core Architecture: Why `rpi5` Is the Main Server + `g14` Is the GPU Node

1. **True 24/7 Availability vs. Laptop Lifecycle**:
   - Hosting public websites, APIs, or webhook listeners on the `g14` means every lid close, reboot, or trip away from home takes your services offline.
   - `rpi5` runs headless on wired Gigabit Ethernet (`192.168.100.167`), draws only ~5–10W idle, and has 1 TB of fast NVMe storage (`ADATA XPG GAMMIX S70 BLADE`).
2. **Zero-VPS Public Hosting Behind TotalPlay CGNAT**:
   - Running `services.cloudflared` on `rpi5` creates an outbound encrypted QUIC tunnel to Cloudflare's global edge.
   - Zero router port-forwarding is required, TotalPlay's CGNAT is completely bypassed, and Cloudflare provides automatic TLS/HTTPS certificates, DDoS protection, and Zero Trust Access authentication for $0/month.
3. **Hybrid Split (`rpi5` Front Door + `g14` RTX 4060 Muscle)**:
   - `rpi5` runs `cloudflared`, `open-webui`, `n8n`, and your web/API services 24/7.
   - Heavy CUDA LLM inference runs on `g14` (`ollama-cuda` with `cudaArches = ["89"]`), and `rpi5` queries `g14` over LAN (`http://192.168.100.197:11434`) whenever `g14` is awake.

## 4. Deployed Configuration Reference (11 November 2026 — ✅ DONE)

### Step 1 — Created the `rpi5` Tunnel & Routed DNS (Ran on `g14`)
```bash
# 1. Created the named tunnel "rpi5" (UUID: 9d4882e5-7305-49f1-a186-5f4ecc31b99a)
cloudflared tunnel create rpi5

# 2. Created the CNAME DNS records in Cloudflare pointing to the tunnel
cloudflared tunnel route dns rpi5 yrrrrrf.dev
cloudflared tunnel route dns rpi5 page.yrrrrrf.dev
cloudflared tunnel route dns rpi5 api.yrrrrrf.dev
cloudflared tunnel route dns rpi5 n8n.yrrrrrf.dev
cloudflared tunnel route dns rpi5 open-webui.yrrrrrf.dev
cloudflared tunnel route dns rpi5 ssh.yrrrrrf.dev
```

### Step 2 — Copied the Tunnel Credentials to `rpi5` (`192.168.100.167`)
```bash
export TUNNEL_ID="9d4882e5-7305-49f1-a186-5f4ecc31b99a"
ssh -i ~/.ssh/id_ed25519 root@192.168.100.167 "install -d -m 0700 /var/lib/cloudflared"
scp -i ~/.ssh/id_ed25519 ~/.cloudflared/${TUNNEL_ID}.json root@192.168.100.167:/var/lib/cloudflared/rpi5.json
ssh -i ~/.ssh/id_ed25519 root@192.168.100.167 "chmod 0600 /var/lib/cloudflared/rpi5.json"
```

### Step 3 — Declarative Config on `rpi5` (`/etc/nixos/src/system/frontier-hosting.nix`)
Imported in `/etc/nixos/src/host/rpi5/rpi5.nix` (alongside an 8 GiB NVMe swapfile `/var/lib/swapfile` at `priority = 10` in `/etc/nixos/src/system/core.nix` so Vite's 8 GiB heap during `open-webui-frontend` builds never triggers OOM):
```nix
{pkgs, ...}: {
  environment.systemPackages = with pkgs; [
    cloudflared
  ];

  # Cloudflare Named Tunnel ("rpi5") -> *.yrrrrrf.dev
  services.cloudflared = {
    enable = true;
    tunnels."9d4882e5-7305-49f1-a186-5f4ecc31b99a" = {
      credentialsFile = "/var/lib/cloudflared/rpi5.json";
      default = "http_status:404";
      ingress = {
        "yrrrrrf.dev" = "http://127.0.0.1:8080";
        "page.yrrrrrf.dev" = "http://127.0.0.1:8080";
        "api.yrrrrrf.dev" = "http://127.0.0.1:3000";
        "n8n.yrrrrrf.dev" = "http://127.0.0.1:5678";
        "open-webui.yrrrrrf.dev" = "http://127.0.0.1:7777";
        "ssh.yrrrrrf.dev" = "ssh://127.0.0.1:22";
      };
    };
  };

  # Always-on Open-WebUI pointing to G14 RTX 4060 Ollama over LAN
  services.open-webui = {
    enable = true;
    host = "127.0.0.1";
    port = 7777;
    environment = {
      OLLAMA_BASE_URL = "http://192.168.100.197:11434";
      WEBUI_URL = "https://open-webui.yrrrrrf.dev";
    };
  };
}
```
